## The Floor (never subject to this loop)

`docs/VOICE_LEDGER_HANDOFF.md` §18's 21 invariants are a constraint, not a target. The ones most load-bearing for this specific slice:

- Three-outcome `RuleOutcome` — `.pass`/`.cannotEvaluate`/`.findings`, never collapsed
- A rule must never claim `.pass` on incomplete coverage, including trivially (item 21 — this exact rule is where that lesson was learned)
- No `.automaticAPI` resolution capability exists or gets added
- Every rule has a non-empty `accountingPrinciple` and at least one `.cannotEvaluate` fixture
- No `Double` in any money path
- The AI kill switch: **there is currently no AI/Claude integration anywhere in this codebase** — the finding surface is 100% deterministic today. Any "plain-English sentence" or narrative text this loop adds must be Core-computed from real fields, never a stand-in for a future AI call, and must keep working exactly the same if AI is ever added and then switched off.
- No live transaction lookup at render time — `Finding` is persisted to `findings.json` and must be fully self-contained; `AppState` does not keep a queryable transaction list in memory after sync, so any UI fix for "evidence shows field names not values" that relies on looking the transaction back up at render time would silently break for every finding loaded after an app restart. Evidence values must be captured **at detection time, in Core.**

A critique of the form "this would look more capable if it claimed more" is rejected on sight and logged below.
